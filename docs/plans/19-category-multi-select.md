# 19 · 카테고리 여러 부위 선택

> **개선** · 폰 · [PRD §4 F-1](../PRD.md) · 결정 근거 [D11](../PRD.md#11-확정-사항)
> **모델은 건드리지 않는다.** 입력 화면만 고친다.

## 무엇이 문제인가

실사용 요일 구성이 이렇다.

| 요일 | 부위 |
| --- | --- |
| 화 | 가슴 · 어깨 · 삼두 |
| 수 | 하체 |
| 목 | 등 · 이두 |
| 금 | 보충 |

화·목은 한 세션에 여러 부위를 한다. 그런데 카테고리를 하나밖에 못 고른다.

**사실 자유 입력은 된다.** `Routine.category` 는 자유 문자열이고 `CategoryField` 에
`TextField` 가 있다. 막고 있는 것은 그 아래 프리셋 칩이다.

```swift
Button(preset) { category = preset }   // 가슴 누르고 어깨 누르면 "어깨" 가 된다
```

**덮어쓰기라 하나만 고를 수 있는 것처럼 보인다.** 손으로 `가슴 / 어깨 / 삼두` 를
타이핑하면 되지만, 칩이 있는데 칩으로 안 되니 그 방법을 떠올릴 이유가 없다.

**우회로도 막혀 있다.** 화요일에 루틴 세 개를 만들어 배정하면 `RoutineScheduler.assign`
이 겹친 요일을 이전 루틴에서 해제한다(A1). 마지막 하나만 남는다. 그래서 지금은
"여러 번 골라 시작" 외에 방법이 없다.

## 왜 배열이 아니라 문자열인가

`category: String` → `[String]` 으로 바꾸고 싶어지는 자리다. 하지 않는다(D11).

- CloudKit 은 배열에 제약이 있다(PRD §7)
- 마크다운 헤더(`## 제목 · 카테고리`)와 워치 payload 가 문자열을 전제한다
- **카테고리는 표시용 이름이지 조회 키가 아니다.** 종목 매칭은 `normalizedName` 이 맡는다

배열로 바꾸면 스키마 · 내보내기 · 가져오기 · 동기화 넷을 동시에 고쳐야 하는데
얻는 것이 없다. 구분자는 사용자의 기존 노트가 쓰던 ` / ` 를 그대로 쓴다.

## 설계

### 칩을 토글로

누르면 붙고, 이미 있으면 뺀다. 순서는 **누른 순서**를 지킨다 — `가슴 / 어깨 / 삼두` 와
`삼두 / 어깨 / 가슴` 은 사용자에게 다른 이름이다.

`TextField` 는 그대로 둔다. 손으로 고친 값도 칩 상태에 반영되어야 하므로,
**칩의 선택 여부는 문자열을 파싱해서 판단한다.** 별도 상태를 두면 두 진실이 생긴다.

### 제안 목록을 실제 기록에서 뽑는다

기본 프리셋에 삼두 · 이두 · 보충이 없다. 이 사용자에게는 절반이 쓸모없는 목록이다.

`ExerciseNameSuggester` 가 이미 같은 문제를 푼다 — 과거 루틴·세션에서 이름을 모아
빈도·최근순으로 정렬한다. 카테고리도 같게 한다. **F-13 으로 5개월치가 들어와 있어
첫 실행부터 제안이 채워진다.**

기록이 없을 때만 기본 목록을 쓴다. 목록도 실사용에 맞춰 고친다 —
`팔` 을 빼고 `삼두` · `이두` · `보충` 을 넣는다.

## 작업 단위

### 1단계 · 계산 (WoofitCore)

- [ ] 1. `CategoryLabel` — ` / ` 로 나누고 합치는 값 타입.
      **빈 조각과 앞뒤 공백을 버린다.** 사용자가 손으로 고치면 `가슴 / ` 같은 값이 나온다
- [ ] 2. `toggling(_:)` — 있으면 빼고 없으면 뒤에 붙인다. 순서 보존
- [ ] 3. `CategorySuggester` — 과거 루틴·세션에서 카테고리를 모아 빈도·최근순.
      **한 칸씩 쪼개서 센다** — `가슴 / 어깨` 는 `가슴` 과 `어깨` 각각 한 번이다
- [ ] 4. 테스트

### 2단계 · 화면

- [ ] 5. `CategoryField` — 칩을 토글로. 선택 여부는 문자열에서 판단
- [ ] 6. 제안 목록을 `CategorySuggester` 에서 받는다. 비면 기본 목록
- [ ] 7. 기본 목록 교체 — `팔` → `삼두` · `이두` · `보충`

| 테스트 | 검증하는 것 |
| --- | --- |
| `가슴 / 어깨 / 삼두` 가 세 조각으로 나뉜다 | 기본 |
| 없는 것을 토글하면 **뒤에** 붙는다 | 순서 보존 |
| 있는 것을 토글하면 빠진다 | 토글 |
| 가운데 것을 빼도 나머지 순서가 유지된다 | 순서 보존 |
| `가슴 /  / 어깨` 의 빈 조각이 버려진다 | 손으로 고친 값 |

| 전부 빼면 빈 문자열이다 | 경계 |

| 제안이 빈도·최근순이다 | 정렬 |

## 완료 기준

1. `swift test` 통과, 위 테스트 존재
2. `xcodebuild build` 통과
3. **화요일 루틴 하나에 `가슴 / 어깨 / 삼두` 를 칩 세 번 눌러 만들 수 있을 것**
4. 그 루틴을 내보낸 마크다운 헤더가 기존 노트와 같은 모양일 것
5. 이미 만든 루틴의 카테고리가 그대로 보일 것 — 마이그레이션 없이 호환

## 주의점

**두 진실을 만들지 않는다.** 칩 선택 상태를 `@State` 로 따로 들면 `TextField` 로 고친
값과 어긋난다. 문자열 하나가 진실이고 칩은 그것을 비추기만 한다.

**기존 데이터는 그대로 열린다.** 모델도 형식도 안 바뀌므로 마이그레이션이 없다.
F-13 으로 들어온 `가슴 / 어깨 / 삼두` 는 이미 이 모양이라 칩 세 개가 켜져서 보인다.

**요일 하나에 루틴 하나 규칙(A1)은 건드리지 않는다.** 이 작업은 그 규칙을 푸는 것이
아니라, 한 루틴이 여러 부위를 담을 수 있게 해서 규칙이 불편하지 않게 만드는 것이다.
