# 20 · F-15 기록 수정

> **개선** · 폰 · [PRD §4 F-15](../PRD.md) · 결정 근거 [D13](../PRD.md#11-확정-사항)

## 왜 필요한가

세션이 끝나면 상세 화면이 **읽기 전용**이다. 실행 중에만 되돌릴 수 있다.

잘못 누른 결과를 못 고치면 **세 기능이 함께 어긋난다** — 직전 기록(F-9), 추이(F-10),
무게 제안(F-11)이 모두 수행값을 근거로 삼기 때문이다. M3 가 붙은 뒤로 이 비용이 커졌다.

## 세션을 다시 열지 않는다

완료된 세션을 `inProgress` 로 되돌려 실행 화면에서 고치는 방법도 있었다. 코드가 거의
안 들지만 **쓰지 않는다**(D13).

세션 이어받기(F-8)를 붙인 뒤로 진행 중 세션은 워치로 릴레이된다. 몇 주 전 세션을 되돌리면
**워치에 지금 운동 중인 것처럼 뜨고**, 운동 세션(F-14)까지 얽힌다.

대신 상세 화면에서 세트를 직접 고치고 세션 상태는 건드리지 않는다.

## 설계

**규칙은 `SessionRecordEditor` 에 둔다.** 화면에 두면 `swift test` 가 닿지 않는다 —
빈 루틴 운동 세션 누수(계획 17)에서 같은 실수를 이미 했다.

```swift
public enum Change {
    case success(actualWeight: Double?)
    case failure(actualReps: Int, actualWeight: Double?)   // 횟수를 타입이 요구한다(D1)
    case skipped
}
```

`failure` 가 `actualReps` 를 연관값으로 갖는 것이 요점이다. **실패는 실제 횟수 없이
표현할 수 없다**는 불변식이 화면이 아니라 타입에서 강제된다.

**`markSuccess` 에 `actualWeight` 를 열었다.** 계획과 다른 무게로 성공한 경우를
담을 자리가 없었다. 볼륨(F-10)이 수행값을 쓰므로 이 값이 있어야 계산이 맞는다.
실행 중에는 넘기지 않는다 — 목표대로 들었다는 뜻이기 때문이다.

**`recordedAt` 을 갱신한다.** 동기화에서 수정이 최신으로 이겨야 상대 기기의 옛 값이
덮어쓰지 않는다(F-8 의 병합 규칙).

## 완료 기준

1. `swift test` 통과 · `xcodebuild build` 통과
2. 세트 줄을 눌러 결과를 바꾸면 목록과 요약이 함께 갱신될 것
3. 실패로 바꿀 때 횟수를 반드시 받을 것
4. 고친 뒤 그 종목의 무게 제안(F-11)이 다시 계산될 것

## 주의점

**일괄 수정은 만들지 않는다.** 한 세트씩 고친다. 여러 세트를 한 번에 바꾸는 화면은
실수했을 때 피해가 크고, 실제로 필요한 경우는 드물다.

**목표 무게·횟수는 고치지 않는다.** 계획은 루틴에 있고 세션은 그 시점의 복사본이다
(PRD §7). 세션의 목표를 고치면 "그때 무엇을 하려 했는가"가 사라진다. 고치는 것은
**실제로 무엇을 했는가**뿐이다.

**마크다운으로 다시 뽑으면 고친 값이 나간다.** 노트가 아카이브라는 전제(§1)가
유지되려면 앱에서 고친 뒤 다시 내보내야 한다.
