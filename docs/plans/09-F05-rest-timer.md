# F-05 · 휴식 시간 측정

> **M2** · 폰 · 워치 · [PRD §4 F-5](../PRD.md#f-5--휴식-시간-측정-폰-워치-m2) · 결정 근거 [D2](../PRD.md#11-확정-사항)

## 요구사항

v1 의 휴식 기능은 **알림이 아니라 측정**이다. 얼마나 쉬라고 알려주지 않고,
얼마나 쉬었는지를 기록에 남긴다.

- 세트 기록 후 **화면을 탭하면 측정 시작**. 경과 시간 실시간 표시
- **다시 탭하면 종료**. 그 시간이 직전 세트의 휴식 시간이 된다
- 측정 중 다음 세트를 기록하면 **자동 종료**. 탭을 깜빡해도 값이 남는다
- 측정하지 않은 세트는 빈 값. 필수가 아니다
- 마크다운 출력에 포함
- **카운트다운 + 햅틱 알림은 M3.** v1 은 스톱워치만

**수용 기준** — 세트 기록 직후 화면 아무 곳이나 탭하면 시작된다. 버튼을 찾을 필요 없음.

## 설계 메모

**타이머를 직접 돌리지 않는다.** `Timer` 로 매초 상태를 갱신하면 배터리를 먹고
백그라운드에서 어긋난다. 대신 `restStartedAt` 을 저장해두고
`TimelineView(.periodic(from:by: 1))` 이 현재 시각과의 차이를 그릴 때마다 계산한다.

```swift
TimelineView(.periodic(from: startedAt, by: 1)) { context in
    Text(WeightFormatter.rest(context.date.timeIntervalSince(startedAt)))
}
```

이러면 **앱이 백그라운드에 갔다 와도 경과 시간이 정확하다.** 저장된 것은 시각뿐이고
경과는 매번 계산되기 때문이다. 세션 복원도 같은 원리로 공짜로 해결된다.

**탭 영역은 화면 전체다.** 버튼을 만들면 수용 기준("버튼을 찾을 필요 없음")에 어긋난다.
단, 성공/실패 버튼 위에서는 그쪽이 우선이어야 한다.

## 주의점

- **`Timer` 를 쓰지 않는다.** 위 설계 메모의 이유. 워치에서 특히 배터리에 직접 영향.
- 휴식은 "이 세트를 끝낸 뒤 쉰 시간"이다. 종목의 마지막 세트에 붙은 휴식은
  다음 종목으로 넘어가기 전의 휴식을 뜻한다.
- 카운트다운을 여기서 만들고 싶어지지만 **M3 다.** 몇 주 써보고 실제로 필요한지 확인한다.
