# 작업 계획

기능별 구현 계획. 각 문서는 [PRD](../PRD.md) 의 요구사항 하나에 대응한다.

계획의 상세도는 마일스톤 거리에 비례한다. M1 은 파일·함수 단위까지, M2 는 구조까지,
M3 는 개요까지만 적었다. **M3 는 데이터가 6~10주 쌓인 뒤에야 무엇을 만들지 알 수 있으므로,
지금 상세하게 적어봐야 대부분 틀린다.**

## M1 작업 순서

```
F-06 내보내기 ──▶ F-07 가져오기 ──▶ 여기서 앱을 쓸 수 있게 된다
                       │
                       ├──▶ F-01 루틴 작성 ──┐
                       │                     ├──▶ F-03 세션 실행 ──▶ F-04 다음 종목
                       └──▶ F-09 직전 기록 ──┘
```

**F-06 → F-07 을 먼저 하는 이유.** 둘 다 순수 함수라 화면 없이 테스트로 완결된다.
그리고 가져오기가 끝나는 순간 **루틴 편집기 없이도 앱을 쓸 수 있다** — 노트에서
마크다운을 붙여넣으면 루틴이 생기기 때문이다. 편집기(F-01)를 먼저 만드는 것보다
실사용까지의 거리가 짧다.

내보내기를 가져오기보다 먼저 하는 이유는, 내보내기 결과가 곧 가져오기의 입력이라
왕복 테스트(export → import → 같은 결과)를 바로 쓸 수 있어서다.

## 문서 형식

각 계획은 같은 구조를 따른다.

- **요구사항** — PRD 에서 무엇을 약속했나
- **선행 조건** — 무엇이 끝나야 시작할 수 있나
- **작업 단위** — 체크박스. 이 순서대로 진행
- **파일** — 무엇을 어디에 만드나
- **테스트 계획** — 무엇을 어떻게 검증하나
- **완료 기준** — 언제 끝난 것으로 보나
- **주의점** — 놓치기 쉬운 것

작업하면서 계획이 틀린 걸 발견하면 **계획 문서를 고친 뒤 진행한다.**
계획과 다르게 구현하고 문서를 방치하면 다음 세션이 잘못된 문서를 믿는다.
