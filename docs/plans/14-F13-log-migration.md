## 변환 규칙 — 실제 데이터로 확정

**세트/횟수** — `3s / 15r` → 15회 목표 세트 3개. 462행 중 **423행이 이 형태**다.

| 예외 | 건수 | 처리 |
| --- | --- | --- |
| `1s / Failure` | 35 | 실패까지 수행. 세트 1개, 목표 횟수 미상 → 0 으로 두고 `skipped` 가 아닌 `success` |
| `3s / Failure` | 1 | 같게 처리 |
| `**1s / 8r**` | 1 | 볼드 제거 후 정상 파싱 |
| 빈 칸 | 2 | 미수행 행. 종목 자체를 만들지 않는다 |

**중량**

| 표기 | 건수 | 처리 |
| --- | --- | --- |
| `40kg` | 359 | 그대로 |
| `65kg 보조` | 49 | 어시스트 머신. 숫자를 그대로 쓰되 **종목명에 "(보조)" 를 남긴다** — 무게가 클수록 쉬운 운동이라 추이 해석이 뒤집힌다 |
| `양쪽 15kg` | 28 | 한쪽 무게로 본다. 숫자만 취한다 |
| `맨몸` | 18 | 0 |
| `40kg, 32kg` 류 | 5 | 세트마다 무게가 다른 경우. **첫 숫자만** 쓰고 건너뛴 값은 issue 로 남긴다 |
| `X` · 빈칸 | 2 | 미수행. 종목을 만들지 않는다 |

**성공 칸** (D8 근사)

| 표기 | 건수 | 처리 |
| --- | --- | --- |
| `✅` | 338 | 전 세트 `success` |
| `❌` | 75 | **마지막 세트만 `failure`**, 실제 횟수는 목표보다 1 적게 근사 |
| `12회` 등 숫자 | 26 | 마지막 세트 `failure`, 그 숫자를 실제 횟수로 |
| `⚠️` · 산문 | 6 | `success` 로 두고 issue 로 남긴다 |
| 빈칸 | 8 | 미수행 행과 함께 나타난다. 종목을 만들지 않는다 |

**종목명** — 볼드(`**`) 를 제거한다. 19행에 있고, 제거해도 고유 종목 수가 41 로 같아 이름이
갈라지지 않는다. `ExerciseName.normalize` 는 그 뒤에 적용된다.

**세션 상태** — 전부 `completed`. `startedAt` 은 날짜의 09:00 으로 둔다(시각 정보가 없다).

## 걸리는 것 두 가지

**① `WorkoutSession.note` 를 추가한다 (확정).** 비고 열에 "3세트 9회 수행하여 4세트 9회 진행",
"55kg 다음이 62kg 라 62kg 로 수행" 같은 **무게를 그렇게 정한 판단 근거**가 들어 있다.
버리기 아까워 모델에 담기로 했다.

- `public var note: String = ""` — CloudKit 제약대로 기본값을 준다
- 마크다운 내보내기에도 쓸 수 있다. 다만 이번 범위는 저장까지고, 내보내기 반영은 별도다
- 종목명 뒤에 붙이는 방식은 **쓰지 않는다** — 이름이 갈라져 직전 기록(F-9)이 끊긴다

**② 세션을 가져오는 경로가 없다.** F-7 은 붙여넣기 하나당 **루틴** 하나를 만든다.
73개 세션을 만들려면 새 경로가 필요하다 → 아래 2단계.

## 작업 단위

두 단계로 나눈다. **1단계만으로도 테스트로 검증이 끝나고**, 2단계는 그 위에 화면만 얹는다.

### 1단계 · 파서와 반영 (WoofitCore)

- [x] 1. `WorkoutSession.note` 추가 — 기본값 `""`
- [x] 2. `ParsedSession` · `ParsedLogEntry` — 값 타입. 미리보기가 이걸 그대로 보여준다
- [x] 3. `LegacyLogParser` — 원본 형식 → 값 타입 (순수 함수, `ModelContext` 를 받지 않는다)
- [x] 4. 변환 규칙 구현 — 위 표 그대로
- [x] 5. `ParsedSession` → SwiftData 반영. **같은 날짜를 두 번 넣지 않도록 멱등하게**
- [x] 6. 테스트 — 대표 행으로 (원본 `운동일지.md` 는 이 저장소 밖에 있어 접근할 수 없다.
      계획 문서의 변환 규칙 표를 그대로 옮긴 합성 행으로 대신했다)

### 2단계 · P9 화면 (폰)

- [x] 7. `LogMigrationView` — 텍스트 붙여넣기 영역. 파일이 52KB 라 큰 입력을 감당해야 한다
- [x] 8. 미리보기 — 세션 수 · 종목 수 · 건너뛴 행과 그 이유
- [x] 9. 적용 — 이미 있는 날짜는 건너뛰고 몇 개를 새로 넣었는지 알린다. 확인 다이얼로그를 한 번 거친다
- [x] 10. 진입점 — 설정(P7) 안에 둔다. 일회성이라 평소 눈에 띄지 않아야 한다.
      **P7 자체가 아직 없어서 이번에 최소 상태로 신설했다** — 탭 하나에 이 항목만 있다.
      마크다운 형식·카테고리 프리셋·증량 폭(F-6, F-11)은 그 기능과 함께 이 화면에 채워진다

## 주의점

**되돌리기가 어렵다.** 73개 세션이 한 번에 들어간다. 잘못 들어가면 F-12(삭제)로 하나씩
지워야 한다. 미리보기에서 충분히 확인시키고, 멱등하게 만들어 재실행이 안전해야 한다.

**어시스트 종목의 무게 방향이 반대다.** `65kg 보조` 는 보조가 **줄수록** 어려워진다.
추이 그래프(F-10)가 이걸 모르면 "무게가 줄었다 = 퇴보" 로 잘못 읽는다. 종목명에 표시를
남기는 것은 최소한의 방어이고, F-10 에서 별도로 다뤄야 한다.

**원본 파일을 건드리지 않는다.** 읽기만 한다. 아카이브는 노트가 맡는다는 전제(§1)가
여기서도 유지된다.
