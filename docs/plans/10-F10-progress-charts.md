# F-10 · 종목별 추이

> **M3** · 폰 · [PRD §4 F-10](../PRD.md#f-10--종목별-추이-폰-m3) · 결정 근거 [D6](../PRD.md#11-확정-사항)

> ⚠️ **이 계획은 개요 수준이다.** M3 는 데이터가 6~10주 쌓인 뒤에 시작한다.
> 그때가 되면 어떤 지표가 실제로 필요한지 알게 되고, 지금 상세히 적은 내용의 상당 부분은
> 틀린 것으로 드러날 것이다. **착수 시점에 이 문서를 다시 쓴다.**

## 요구사항

- 종목을 고르면 수행 이력을 시간순으로
- 세션별 최고 무게, 총 볼륨, 성공률 그래프 (Swift Charts)
- 추정 1RM(Epley) 추이
- **정체 구간을 눈으로 확인하는 것**이 목적. 세부 수치 열람이 아니다

## 선행 조건

- M1 · M2 완료
- **실사용 데이터 6~10주 축적** — 이것이 진짜 선행 조건이다
- ✅ 폰이 전체 세션을 영구 보관(D3) — 이미 확보

## 착수 전 확인할 것

착수 시점에 실제 데이터를 보고 답한다. 지금 답하면 추측이다.

- 어떤 지표를 실제로 보고 싶었나? (최고 무게 / 볼륨 / 성공률 / 1RM 중 무엇이 쓸모 있었나)
- 기간 단위는? (세션별 / 주별 / 월별)
- 종목을 고르는 방식은? (목록 / 최근 순 / 부위별)
- 정체를 어떻게 정의할 것인가? (N주간 최고 무게 미갱신 등)

## 테스트 계획 (예상)

집계는 순수 함수이므로 전부 테스트 가능하다.

- 종목별로 세션을 시간순으로 묶는다
- 세션별 최고 무게·총 볼륨·성공률 계산
- 1RM 추정값이 Epley 공식과 일치
- 건너뛴 세트는 볼륨에서 제외
- 중단된 세션도 이력에 포함
- 데이터가 1건뿐일 때 그래프 입력이 깨지지 않음

## 어시스트 종목 — 무게 방향이 반대다

**F-13 으로 과거 일지를 옮기면 곧바로 드러나는 문제다.** 어시스트 풀업·친업은 기록이
`65kg 보조` 형태이고, 보조 중량이 **줄수록 어려워진다.** 일반 종목과 정반대다.

```
일반 종목   40kg → 45kg   무게가 늘었다 = 향상
어시스트    65kg → 60kg   보조가 줄었다 = 향상   ← 그래프는 "하락"으로 그린다
```

과거 일지에 49행(어시스트 풀업 22 · 친업 20 등)이 있어 무시할 양이 아니다. 그대로 두면
**향상을 퇴보로 읽는 그래프**가 나온다. 정체 구간을 눈으로 확인하는 것이 이 계획의 목적인데
(위 요구사항) 방향이 뒤집히면 목적 자체가 무너진다.

**착수 시 정할 것**

- 어시스트 종목을 어떻게 식별하나 — F-13 이 종목명에 "(보조)" 를 남기기로 했지만, 앞으로
  앱에서 입력하는 기록에는 그 표시가 없다. 종목에 속성을 두는 방법도 있다
- 그래프에서 어떻게 다루나 — 축을 뒤집을지, 부호를 바꿔 "보조 감소량" 으로 그릴지,
  아예 별도 차트로 뺄지
- 볼륨·1RM 추정을 적용할 수 있나 — 보조 기구에 Epley 공식을 그대로 쓰는 것이 맞는지

지금 답을 정하지 않는다. **F-10 착수 시점에 실제 데이터를 그려보고 정한다** — 이 계획의
다른 항목들과 같은 이유다.

## 주의점

- **차트를 예쁘게 만드는 데 시간을 쓰지 않는다.** 정체 구간이 보이면 목적을 달성한 것이다.
- 볼륨 계산은 `performedWeight × performedReps` 를 쓴다. 목표가 아니라 실제 수행값이다.
- 종목 매칭은 `normalizedName` 기준. F-09 와 같은 규칙을 쓴다.
