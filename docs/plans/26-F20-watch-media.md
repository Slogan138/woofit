# 26 · F-20 워치 미디어 제어

## 요구사항

[PRD F-20](../PRD.md)의 운동·휴식 ↔ 미디어 가로 페이지를 제공한다.

## 선행 조건

- 계획 18의 워치 세트 화면, 계획 17의 운동 세션 유지, F-8 동기화.

## 작업 단위

- [x] `WatchSetView`에 선택 상태를 가진 표준 가로 `TabView`와 `NowPlayingView`를 추가한다.
- [x] 미디어 페이지에서는 운동 화면의 입력과 더블 탭 단축키를 비활성화한다.
- [x] 페이지 이동으로 러너를 재생성하지 않고 동기화·종료 관찰은 페이지 밖에서 유지한다.
- [x] 휴식 유지와 원격 기록 반영의 도메인 회귀 테스트를 추가한다.
- [x] 도메인 테스트와 워치 포함 시뮬레이터 빌드를 검증한다.
- [ ] Ultra 3에서 스와이프·음량·더블 탭·재생 소스와 재활성화를 검증한다.

## 파일

- `WoofitWatch Watch App/Features/WatchSetView.swift`: 페이지와 입력 범위.
- `WoofitCore/Tests/WoofitCoreTests/SessionRunnerTests.swift`: 휴식과 동기화 회귀 검증.

## 테스트 계획

- 화면 갱신용 조회와 시간 경과가 기록·초점·휴식 시작 시각을 변경하지 않고 경과 시간만 증가한다.
- 상대 기기 기록을 반영해도 진행 중 휴식이 유지된다.
- UI 실기기: 운동/휴식에서 한 번씩 스와이프 왕복, 재생 없음·폰/워치 재생 각각 확인.
- 미디어의 Crown·더블 탭이 숨은 세트를 기록하지 않고 가로 스와이프가 휴식을 토글하지 않는다.
- 재활성화·장시간 휴식은 페이지를 유지하고, 폰의 완료·중단은 기존 종료 흐름을 따른다.

## 완료 기준

`swift test`와 워치 포함 앱 빌드 통과. 실제 재생 제어와 제스처는 Ultra 3에서 별도 확인한다.
도메인 테스트는 UI 제스처나 시스템 플레이어 동작을 검증하는 테스트로 간주하지 않는다.

## 주의점

`NowPlayingView`는 스크롤 없는 전체 페이지에 단독 배치한다. 선택 상태를 휴식 시각이나
scenePhase와 연결하지 않는다. 페이지 이동에 `onDisappear` 종료 처리를 추가하지 않는다.

## 검증 결과

- `swift test`: 276개 통과(휴식 유지·원격 반영 회귀 2개 추가).
- 워치 포함 iOS Simulator 빌드 통과(`CODE_SIGNING_ALLOWED=NO`).
- Ultra 3 실기기 재생·제스처·재활성화 검증은 대기 중.

## 레이아웃 회귀 수정 · 2026-11-03

실기기에서 미디어의 하단과 오른쪽이 잘린다는 보고가 있다. 운동과 미디어를 감싼
공통 `NavigationStack`과 페이지 표시 영역이 전체 화면 플레이어를 제한하는지 확인한다.

- 운동용 `NavigationStack`·제목·중단 버튼을 운동 페이지 내부로 이동한다.
- 미디어는 스크롤 없는 전체 화면으로 표시하고 페이지 표시 점의 공간을 제거한다.
- 세션 관찰·시트·종료 처리는 페이지 바깥에 유지한다.
- 회귀 확인: Ultra 3에서 오른쪽 음량 표시와 하단 버튼이 전부 보이고 눌리는지,
  왕복 후 운동 제목·중단 버튼·스크롤·휴식이 정상인지 확인한다.
- 도메인 동작은 바꾸지 않는다. 기존 테스트와 앱 빌드를 실행하되 시각 회귀는
  실기기에서 확인할 때까지 검증 대기로 남긴다.

수정 검증: 도메인 테스트 276개와 워치 포함 iOS Simulator 빌드 통과.
시각 회귀는 아직 실기기에서 재확인하지 않았다. 실제 음악 재생 중 하단·우측 조작 영역,
운동 페이지의 스크롤·중단 버튼·실패 입력과 휴식 왕복을 확인해야 한다.

근거: [Apple NowPlayingView](https://developer.apple.com/documentation/watchkit/nowplayingview)는
스크롤 없는 전체 화면에 다른 요소 없이 배치하도록 안내한다.

## 미디어 내부 크기 보정 · 2026-11-03

사용자 사진에서 오른쪽·하단 검은 띠와 좌상단 치우침이 확인됐다. watchOS 27.2,
49mm 시뮬레이터에서도 배경에 색을 넣으면 211×257pt 페이지 안의 시스템 미디어가
205×251pt 영역까지만 그려지는 현상이 재현된다. `frame` 확대만으로는 해결되지 않았다.

- watchOS 27.2의 211×257pt 뷰포트에만 내부 렌더링 크기 차이를 보정한다.
- 다른 화면 크기와 OS 버전은 시스템 기본 배율을 사용한다.
- 보정은 시스템 플레이어 전체에 적용하며 임의 버튼·재생 로직은 추가하지 않는다.
- 표준 예외를 AGENTS.md에 기록한다. 시스템 수정 시 제거할 수 있게 적용 범위를 제한한다.
- 진단 배경으로 보정 전후의 오른쪽·하단 경계와 컨트롤 배치를 비교한다.
- 진단용 시작 화면·배경·로그는 제품 코드에서 제거한 뒤 테스트·빌드를 확인한다.
- 실기기 음악 재생·터치·Crown·스와이프 왕복은 재확인 대기로 남긴다.

검증 결과: 명시적인 프레임 확대는 내부 렌더링 크기를 바꾸지 않았다. 전체 시스템 뷰에
좌상단 기준 가로 211/205 · 세로 257/251 배율을 적용한 뒤, 진단 배경 스크린샷에서
우측·하단 경계가 화면 끝까지 채워지고 재생 버튼이 가운데로 정렬됨을 확인했다.
연결된 실기기의 OS도 27.2로 확인했다. `WatchMediaView`에 이 버전·크기 조건만 적용하며,
소스의 기본 페이지는 운동으로 유지한다. 진단용 시작 화면·붉은 배경·파일 로그는 제거했다.
실기기 재생 중 터치·Crown·스와이프는 사용자 재확인 대기다.

최종 코드 검증: `swift test` 276개 및 워치 포함 iOS Simulator 빌드 통과.
