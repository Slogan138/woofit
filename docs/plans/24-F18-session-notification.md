# 24 · F-18 세션 미종료 알림

> **개선** · 폰 · [PRD §4 F-18](../PRD.md) · 결정 근거 [D14](../PRD.md#11-확정-사항)
> **계획 21 의 3단계를 앱 밖으로 내보내는 일이다.** 새 판단을 만들지 않는다.

## 왜 필요한가

계획 21 은 마지막 기록 후 20분·45분에 안내를 띄운다. **그런데 앱 안에서만 뜬다.**

정작 잡으려는 상황이 그렇지 않다. 운동을 마치고 중단을 누르지 않은 채 헬스장을
나서면, 그때 앱은 주머니 안이거나 이미 내려가 있다. 손목을 다시 들 일이 없으니
배너를 볼 일도 없다.

```
지금:  운동 끝 → 앱 안 봄 → 배너는 떴지만 아무도 못 봄 → 세션이 밤새 열려 있음
목표:  운동 끝 → 20분 뒤 알림 → 손목에서 확인 → 중단
```

## 무엇을 쓰는가

**로컬 알림(`UNUserNotificationCenter`)이다.** 원격 푸시(APNs)가 아니다.

| | 로컬 알림 | 원격 푸시 |
| --- | --- | --- |
| 보내는 주체 | 기기 자신 | 서버 |
| 유료 계정 | 불필요 | 필요 |
| 이 앱 | **쓸 수 있다** | 서버가 없어 애초에 불가(§9) |

## 설계

### 폰이 보낸다

워치도 보낼 수 있지만 **한 곳만 보내야 한다.** 둘 다 걸면 알림이 두 번 온다.

폰을 고르는 이유는 셋이다.

- **폰은 항상 최신 상태를 갖는다.** 모든 기록이 폰으로 릴레이된다(F-8)
- **워치 앱은 죽는다.** 세션이 끝난 뒤에는 운동 세션도 끝나 앱이 곧 내려가고,
  그러면 예약을 갱신할 주체가 사라진다
- **권한을 한 곳에서만 묻는다**

폰 알림은 잠겨 있을 때 **손목으로 전달된다.** 워치에서 보내는 것과 결과가 같다.

### 예약 시각은 이미 계산돼 있다

```swift
SessionLifetime.nudgeDates(idleSince:thresholds:)   // 계획 21
```

화면이 `TimelineView` 에 쓰는 그 값을 알림 예약에도 그대로 쓴다. **판단이 한 곳에
있어야 배너와 알림이 어긋나지 않는다.**

설정에서 `0`(사용 안 함)으로 둔 임계값은 예약하지 않는다(F-3).

### 기록할 때마다 다시 건다

세트를 기록하면 `lastActivityAt` 이 밀리므로 예약도 밀어야 한다. 기존 예약을 지우고
다시 건다 — 로컬 알림이라 비용이 없다.

**거는 자리는 잠금화면을 갱신하는 자리와 같다**(F-16). 폰이 주머니에 있어도 워치
기록이 동기화 수신 경로로 들어오고, 그 자리에서 함께 처리한다. 두 기능이 같은
신호를 쓰므로 한쪽만 갱신되는 어긋남이 생기지 않는다.

| 시점 | 하는 일 |
| --- | --- |
| 세션 시작 | 예약 |
| 세트 기록 (로컬·원격 무관) | 지우고 다시 예약 |
| 완료 · 중단 | 지운다 |
| 앱이 앞으로 나옴 | 살아 있는 세션이 없으면 지운다(그물) |

### 45분 알림에는 중단 버튼을 단다

20분은 묻기만 한다. 45분은 알림에서 바로 끝낼 수 있게 한다 — **앱을 열어야 끝낼 수
있으면 지금과 달라지는 게 없다.**

`UNNotificationAction` 으로 `중단` 을 달면 탭 한 번으로 처리되고, 처리는 앱이
백그라운드에서 깨어나 수행한다. `계속` 은 두지 않는다. 알림을 무시하는 것이 곧
계속이고, 버튼이 둘이면 손목에서 잘못 누르기 쉽다.

### 앱이 떠 있으면 알림을 띄우지 않는다

배너가 이미 보이는 화면에 알림까지 겹치면 같은 말을 두 번 한다.
`willPresent` 에서 빈 옵션을 돌려준다.

### 권한은 첫 세션 시작 직전에 묻는다

앱 첫 실행 때 물으면 무엇에 쓰는지 모르는 상태에서 거부당한다(F-14 와 같은 판단).
거부해도 앱은 그대로 동작하고 **앱 안 배너는 계속 뜬다.**

## 작업 단위

### 1단계 · 예약 목록 (WoofitCore)

`SessionNotificationPlan` — 세션과 임계값과 현재 시각을 받아 **무엇을 언제 걸지**
값으로 돌려준다. `UNUserNotificationCenter` 를 모른다.

```swift
struct ScheduledNudge { let kind: Nudge; let fireDate: Date }
static func requests(for session: WorkoutSession?, thresholds: NudgeThresholds, at date: Date) -> [ScheduledNudge]
```

살아 있는 세션이 없으면 빈 배열이다 — **"전부 지우라"는 뜻**이고, 그 판단까지 여기 있다.

### 2단계 · 예약 (폰)

`SessionNotificationScheduler` — 1단계가 준 목록을 `UNUserNotificationCenter` 에 건다.
기존 요청을 식별자로 지우고 다시 건다. 권한 요청과 `willPresent` 처리도 여기.

### 3단계 · 배선 (폰)

잠금화면을 갱신하는 자리마다 한 줄씩 더한다 — `WatchSyncService` 수신 경로,
`SessionRunnerView` 의 기록·휴식 변화, `RootView` 의 앞으로 나옴.

`중단` 액션 처리는 `UNUserNotificationCenterDelegate` 에서 세션을 찾아 `abandon()`
한 뒤 최종 상태를 워치로 보낸다(F-8).

## 테스트 계획

예약 **목록**은 순수 함수라 전부 `swift test` 로 돈다. 알림 전달 자체는 실기기에서
확인한다 — `WatchSyncService` 와 같은 판단이다(계획 08).

| 테스트 | 보장 |
| --- | --- |
| 진행 중 세션이면 20분·45분 두 건을 건다 | 기본 |
| 예약 시각은 마지막 기록 기준이다 | 경과 시간이 아님(D14) |
| 임계값이 0 이면 그 건은 걸지 않는다 | 설정(F-3) |
| 둘 다 0 이면 아무것도 걸지 않는다 | 전부 끄기 |
| 끝난·중단된 세션이면 빈 목록이다 | **"전부 지우라"** |
| 세션이 없어도 빈 목록이다 | 같음 |
| 이미 지난 시각은 걸지 않는다 | 복원 직후 과거 알림이 즉시 울리지 않게 |

## 완료 기준

1. `cd WoofitCore && swift test` 통과
2. 위 테스트 존재
3. `xcodebuild build -scheme Woofit` 통과
4. 실기기 — 세션을 열어둔 채 20분 두면 **손목에 알림이 온다**
5. 실기기 — 45분 알림의 `중단` 을 누르면 **앱을 열지 않고** 세션이 중단되고,
   워치에도 반영된다
6. 실기기 — 앱을 열어둔 상태에서는 알림이 뜨지 않는다(배너만)
7. PRD F-18 추가

## 주의점

**세션을 끝낼 때 반드시 지운다.** 남으면 운동이 끝난 한참 뒤에 "아직 운동 중인가요?"
가 울린다. 계획 21·22 가 각각 세션과 잠금화면에서 겪은 것과 같은 종류의 누수다.

**복원 직후를 조심한다.** 며칠 전 세션이 복원되는 경우는 계획 21 이 막았지만, 예약
시각이 이미 지난 경우는 여전히 생길 수 있다 — 그때 즉시 울리면 안 된다.

**알림은 앱을 대신하지 않는다.** 거부해도 앱 안 배너는 그대로 뜬다. 알림이 없으면
불편할 뿐 기능이 사라지지는 않아야 한다(F-14 권한과 같은 태도).
