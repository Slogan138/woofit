# F-11 · 다음 무게 제안

> **M3** · 폰 · [PRD §4 F-11](../PRD.md#f-11--다음-무게-제안-폰-m3) · 결정 근거 [D6](../PRD.md#11-확정-사항) · [D12](../PRD.md#11-확정-사항)

> 이 문서는 **실제 기록을 보고 다시 썼다**(2026-08-30). 이전 판은 개요였고
> "착수 시점에 실제 증량 패턴을 보고 다시 쓴다"고 남겨둔 질문들이 있었다.
> 아래는 5개월치(73세션 · 470행 · 41종목)를 집계한 답이다.

## 데이터가 말한 것

### ① 기본값 2.5kg 은 틀렸다

무게가 바뀐 31회를 모두 세어봤다.

| 변화 폭 | 횟수 |
| --- | --- |
| +5kg | 8 |
| −5kg | 5 |
| +8kg | 5 |
| +1kg · +2kg | 각 3 |
| +7kg · +10kg | 각 2 |
| **+2.5kg** | **1** |

이전 판과 PRD 가 기본값으로 삼았던 2.5kg 는 **31회 중 단 한 번** 쓰였다.
그대로 만들었으면 거의 모든 제안이 실제와 어긋났을 것이다.

### ② 증량 폭은 사용자가 아니라 기구가 정한다

| 종목 | 시작 | 실제 증량 |
| --- | --- | --- |
| 덤벨 숄더 프레스 | 5kg | +1 · +1 · +1 |
| 원 암 덤벨 로우 | 12kg | +2 · +2 |
| 레그 컬 | 30kg | +5 · +5 |
| 랫풀 다운 | 30kg | +10 · +8 |
| 아웃 타이 | 55kg | +7 · +8 |
| 핵스쿼트 | 40kg | +10 |

덤벨은 1~2kg, 머신은 5~10kg 다. **하나의 설정값으로 덮을 수 없다.**
설정 화면에 "증량 폭" 하나를 두는 이전 설계는 성립하지 않는다.

### ③ 올릴 때는 직전이 성공이었다

| 올리기 직전 세션 | 횟수 |
| --- | --- |
| ✅ | 22 |
| ❌ | 1 |
| 빈칸 | 1 |

**"전 세트 성공이면 증량"이라는 규칙 자체는 실제 패턴과 맞다.**
연속 성공 횟수는 중앙값 1.5회, 최빈 1회다 — 한 번 성공하면 대체로 바로 올린다.

### ④ 감량에는 근거가 없다

내린 7회 중 **5회는 직전이 성공(✅)** 이었다. 실패해서 내린 것이 아니라 기구를
바꿨거나 종목 구성을 조정한 경우다. 실패 → 감량이라는 규칙은 이 기록에 없다.

### ⑤ 절반 이상의 종목은 배울 것이 없다

| 증량 경험 | 종목 수 |
| --- | --- |
| 0회 | **27** |
| 1회 | 6 |
| 2회 | 6 |
| 3회 | 2 |

41종목 중 **27종목은 한 번도 무게를 올리지 않았다.** 그 종목들에는 배울 폭이 없다.

## 정한 것

### 제안은 세 단계로 내려간다

근거가 강한 순서다. **어느 단계에서 나온 제안인지 이유 문구로 드러낸다.**

| 순위 | 규칙 | 근거 |
| --- | --- | --- |
| 1 | **과거에 실제로 쓴 다음 무게** | 덤벨 숄더가 5·6·7·8 을 거쳤다면 7 다음은 8 이다. 그 기구에 그 무게가 있다는 것이 이미 증명됐다 |
| 2 | **그 종목의 관측 증량 폭** (최빈값) | 14종목이 여기 해당한다 |
| 3 | **무게대별 기본 단위** — 10kg 미만 +1, 30kg 미만 +2.5, 그 이상 +5 | 나머지 27종목. 관측 비율 중앙값이 20% 였지만 그대로 쓰지 않는다 — 저중량 종목의 큰 비율이 끌어올린 값이라 과대 제안이 된다. **모자란 쪽으로 틀리는 편이 낫다** |

### 감량은 제안하지 않는다

데이터에 근거가 없다(④). 직전이 실패면 **유지**를 제안하고 이유에 그 사실을 적는다.
감량 판단은 컨디션·부상 같은 앱이 모르는 정보에 달려 있다.

### 증량 폭 설정을 만들지 않는다

이전 판의 "증량 폭은 설정에서 조정, 기본 2.5kg" 를 **뺀다**(D12). 종목마다 다른 값을
설정 하나로 덮을 수 없고, 종목별 설정을 만들면 41개를 손으로 채워야 한다.
기록에서 배우는 쪽이 정확하고 손이 덜 간다.

### 조건은 전 세트 성공

직전 세션에서 그 종목의 세트가 **전부 성공**일 때만 증량을 제안한다(③).
건너뛴 세트가 있으면 성공으로 치지 않는다 — 수행하지 않은 것을 근거로 삼을 수 없다.

## 작업 단위

### 1단계 · 규칙 (WoofitCore)

- [ ] 1. `WeightSuggestion` — 제안 무게 · 근거 단계 · 이유 문구
- [ ] 2. `ProgressionRule.suggest(for:in:)` — 위 세 단계. 순수 함수
- [ ] 3. 1순위 구현 — 그 종목의 과거 무게 집합에서 직전 무게보다 큰 최솟값
- [ ] 4. 2순위 구현 — 관측 증량 폭의 최빈값. 동률이면 작은 쪽
- [ ] 5. 3순위 구현 — 무게대별 기본 단위
- [ ] 6. 직전이 실패면 유지 제안. 직전 기록이 없으면 제안하지 않는다
- [ ] 7. 테스트

### 2단계 · 화면

- [ ] 8. 루틴 편집기에 제안 표시 — 종목마다 한 줄. 이유를 함께 보여준다
- [ ] 9. 일괄 적용 — 루틴 전체의 제안을 한 번에 반영. **자동 적용은 하지 않는다**

| 테스트 | 검증하는 것 |
| --- | --- |
| 과거에 5·6·7·8 을 썼고 직전이 7 이면 8 을 제안한다 | 1순위 |
| 직전이 그 종목의 최고 무게면 관측 증량 폭을 더한다 | 2순위 |
| 증량 이력이 없는 종목은 무게대별 기본 단위를 쓴다 | 3순위 |
| 5kg 종목은 +1, 20kg 은 +2.5, 50kg 은 +5 | 무게대 경계 |
| 직전에 실패한 세트가 있으면 무게를 유지한다 | 감량하지 않는다(④) |
| 건너뛴 세트가 있으면 전 세트 성공으로 치지 않는다 | 수행하지 않은 것을 근거로 쓰지 않는다 |
| 직전 기록이 없으면 제안이 없다 | 경계 |
| 제안에 어느 단계에서 나왔는지가 남는다 | 이유 표시 |

## 완료 기준

1. `swift test` 통과, 위 테스트 존재
2. `xcodebuild build` 통과
3. **가져온 5개월치로 덤벨 숄더 프레스에 8kg 다음이 제안될 것** — 1순위가 아니라
   2순위(관측 폭 +1kg)로 내려가 9kg 가 나와야 한다
4. 아웃 타이는 70kg 에서 +7 또는 +8 이 제안될 것
5. 증량 이력이 없는 종목(예: 사이드 레터럴 레이즈 5kg)은 +1kg 가 제안될 것
6. 제안을 적용하지 않아도 루틴이 그대로일 것

## 주의점

**자동으로 바꾸지 않는다.** 제안이 틀렸을 때 사용자가 모르는 채로 루틴이 바뀌면 기능
전체를 못 믿게 된다. 이전 판의 이 경고는 그대로 유효하다.

**이유 없는 숫자를 보여주지 않는다.** 세 단계 중 어디서 나왔는지에 따라 신뢰도가 다르다.
3순위 제안은 "이 종목은 올려본 적이 없어 기본 단위로 제안합니다" 처럼 약한 근거임을
드러낸다.

**F-10 이 정체를 알려주고 F-11 이 다음 수를 제안한다.** 지금 실제 데이터는 대부분의
종목이 정체 상태다(F-10 검증). 이 기능이 겨냥하는 것이 바로 그 상황이다.

**모자란 쪽으로 틀린다.** 과대 제안은 실패를 부르고 실패가 반복되면 제안을 끄게 된다.
관측 비율 중앙값 20% 를 그대로 쓰지 않은 이유다.
